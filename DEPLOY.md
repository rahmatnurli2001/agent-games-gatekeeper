# Proof Gatekeeper — deployment

## Status: code complete + proof pipeline verified locally. NOT yet live.

The server (`server.js`) is a plain Node.js HTTP service. It is **fully tested
locally** (see `GATEKEEPER-BUILD.md`): 12/12 trap cases, 15/15 live HTTP
checks, Groth16 proofs generate in ~270–770 ms and verify against the
tournament's registered verification key. What is missing is a **public host**.

## Blocker: Cloudflare Workers (free tier) CANNOT run this

Measured and documented — do not retry silently:

| Constraint | Workers Free | This agent needs |
|---|---|---|
| CPU time / HTTP request | **10 ms** (Cloudflare docs, updated 2026-11-13) | **~270–770 ms** of pure CPU per Groth16 proof (snarkjs `fullProve`) |
| Worker size | 1 MB (older docs) / 64 MiB (newer docs) | wasm 1.7 MB + zkey 310 KB + snarkjs — only fits if assets are fetched at runtime, which does not fix the CPU limit |

The CPU limit alone is 27–77× too small. Even the fastest Groth16 prover
(rapidsnark, ~50 ms) is 5× over. A free-tier Worker would be killed
mid-proof on every task. **This is definitive, not a configuration issue.**

Two real options:

### Option A — Railway (recommended, free trial, proven)

The reference implementation this agent is based on was deployed to Railway
successfully. Railway runs plain Node.js and gives a stable public HTTPS URL.

1. Push this folder to a GitHub repo (e.g. `agent-games-gatekeeper`).
   - Do NOT commit `.env` (it is not in this folder yet — create it from
     `.env.example` only on the host). The `circuits/` files (wasm + zkey)
     are public tournament artifacts and are safe to commit.
2. Create a Railway account (railway.app), **New Project → Deploy from
   GitHub repo**, pick the repo. Railway detects Node.js and runs `npm start`.
3. In Railway → Variables, set:
   - `AGENT_GAMES_HMAC_SECRET` — (leave blank for now; set after step 5)
   - `GATEKEEPER_TASK_ID_MODE=keccak`
4. Railway assigns a public domain, e.g.
   `https://agent-games-gatekeeper-production.up.railway.app`.
   Check `https://<domain>/health` — it must show
   `"selfTest": "PASS (APPROVE proof verifies locally)"`.
5. In the Agent Games dashboard (Control Room → Register agent), register
   the endpoint **with the full handler path**:
   `https://<domain>/gatekeeper`
   Then **Rotate Secret**, copy the one-time plaintext, paste it as
   `AGENT_GAMES_HMAC_SECRET` in Railway, and redeploy/restart.
6. Run preflight from the dashboard — it must pass. Then run a practice
   task and confirm the proof is accepted (this also confirms the
   `taskId` mapping — see "Open items" below).

### Option B — Cloudflare Workers Paid ($5/month)

If the user prefers to stay on Cloudflare: upgrade the account to Workers
Paid (CPU 30 s/request, default). Then the prover must be **ported** to the
Workers runtime (no Node `fs` — fetch the wasm/zkey from
`agentgames.zkverify.io/circuits` at cold start and cache them in the
isolate; rewrite the snarkjs file loading to use `ArrayBuffer`s). This is a
real porting job, not a redeploy. Only pursue it if Railway is not an option.

## What the user enters in Control Room → Register agent

| Field | Value |
|---|---|
| Endpoint URL | `https://<your-public-domain>/gatekeeper` (full handler path — NOT the bare domain) |
| Event | Proof Gatekeeper |
| HMAC secret | Generated by the platform at registration; shown ONCE via **Rotate Secret**. Copy it into the host as `AGENT_GAMES_HMAC_SECRET` and restart. The agent cannot work without it (preflight fails with a signature error). |

## Open items (confirm in practice mode — cannot be verified locally)

1. **`taskId` mapping.** The envelope `task_id` (e.g. `gk_24_9d1`) is a
   string; the circuit needs a field element. Default: `keccak256(task_id)`
   mod field prime (`GATEKEEPER_TASK_ID_MODE=keccak`). Alternatives
   (`numeric`, `hex`) are one env-var switch in `gatekeeper/prove.js`. If
   a practice task's proof is rejected, switch the mode and retry.
2. **HMAC header format.** Assumed lowercase hex HMAC-SHA256 of the raw
   body. If preflight fails, set `AGENT_GAMES_HMAC_FORMAT=sha256=`
   (the `sha256=<hex>` form) and retry.
3. **Kurier (optional).** The response already carries the local Groth16
   proof, which is what the platform re-verifies. Kurier (on-chain
   finalization) is a best-effort extra and is NOT configured — it is not
   needed for scoring.
